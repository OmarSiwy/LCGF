# Styling, tokens and component recipes

`lcgf.style` resolves borrowed declarations into the existing `Style` and `TextStyle`
values. `lcgf.theme_recipes` supplies optional component builders that consume those values.
You can use either layer independently, keep using direct `Frame`/`Tree` calls, or run the
layout and painting passes yourself. There is no required registry, allocator, retained style
tree or renderer callback.

The [research inventory](../research/styling/inventory.md) describes the
broader capability groups. A supported native profile is not a claim of full CSS, SVG, DTCG,
MathML or platform accessibility conformance.

## Resolve ordinary typed data

Declarations name a property and its source. Omission means no override; `inherit`, `initial`,
literal zero and transparent colors remain distinct. Matching rules apply in slice order,
property by property; local declarations apply last. There is no hidden specificity rule.

```zig
const s = lcgf.style;
const rules = [_]s.Rule{
    .{ .part = s.Parts.root, .declarations = &.{
        s.set(.fill, .black),
        s.set(.radius, 4),
        s.set(.text_size, 16),
    } },
    .{ .part = s.Parts.root, .require = .{ .selected = true },
        .declarations = &.{s.set(.border_width, 2)} },
    .{ .part = s.Parts.root, .require = .{ .hovered = true },
        .forbid = .{ .disabled = true },
        .declarations = &.{s.set(.fill, .white)} },
};
var origins: [s.properties.count]s.Origin = undefined;
const computed = try s.resolve(.{
    .rules = &rules,
    .states = .{ .selected = true, .hovered = true },
    .local = &.{s.set(.fill, .transparent)},
}, &origins);
_ = frame.textStyled("Resolved", computed.text, computed.box);
```

The transparent local fill leaves the selected border intact. `s.patch(.{ ... })` produces
an ordinary declaration array from checked field names. Constant inputs can be resolved at
compile time; runtime inputs use the same function.

The property catalog covers native fill, border, radii, opacity, transform/origin, texture,
material parameters, UV coordinates, dimensions and constraints, physical padding, gap,
alignment, shrink/floating/offset, clipping, scrolling, text color/size/font/wrap,
participation and cursor. `properties.Type`, `validate`, `initial`, `metadata`, `changed`
and `interpolate` expose the contract without a runtime registry. Invalidation distinguishes
paint, measurement, layout, hit geometry, semantics, descendants and platform output.

Paint-only color changes do not request text measurement or layout. Radii, clipping and
transforms also affect descendant or hit geometry. Compatible numeric/vector values can be
interpolated; incompatible size modes and discrete values switch discretely. Color
interpolation uses premultiplied color arithmetic. The caller still schedules any animation
and decides which affected passes to run.

Advanced brushes, prepared decorations, effects, text shaping and layout side tables retain
their own typed inputs. They are not copied into a giant per-node style structure. Material
and texture identifiers continue to refer to caller-owned renderer resources.

## Keep semantic token identity

```zig
const entries = [_]s.tokens.Entry{
    s.tokens.literal(.fill, .from("color.accent"), .white),
    s.tokens.literal(.fill, .from("color.danger"), .white),
    s.tokens.alias(.from("button.face"), .from("color.accent")),
};
const scopes = [_]s.tokens.Scope{.{ .entries = &entries }};
const computed = try s.resolve(.{
    .tokens = .{ .scopes = &scopes },
    .scope = 0,
    .local = &.{s.token(.fill, .from("button.face"))},
}, null);
```

Equal colors remain different roles. Replacing the accent entry later changes its users;
an equal literal remains a literal. A scope's last matching entry wins, and the nearest
scope wins over its ancestors. An alias resolves from the scope where it is defined, so a
child shadowing an unrelated name does not reinterpret an ancestor's alias. Missing tokens,
invalid scope chains and alias cycles return explicit errors.

`tokens.scale` writes a validated nondecreasing numeric scale into caller storage.
`theme_recipes.tokenRows` bridges the existing theme's color, spacing, radius and text-size
scales to semantic entries. Composite typography, elevation, borders and transition values
can be supplied directly or generated by the importer below. Density is an explicit token
choice; physical strokes and fixed image assets are not implicitly rescaled with spacing.

## Compose parts, variants and states

`Recipe` contains part defaults and ordered rules. A `Use` supplies the token scope, selected
variant IDs, state bits, environment, optional parent computed values and local declarations.
Every required variant/state must match; forbidden state bits must be absent. Applications
can invent part, token and variant IDs without registration.

The runtime button exposes its useful construction stages:

```zig
const recipes = lcgf.theme_recipes;
const control = try recipes.beginButton(&frame, .from("save"), .{
    .variants = &.{.from("small")},
    .states = .{ .invalid = validation_failed },
});
_ = try recipes.directionalIcon(&frame, &control, icon_texture, icon_uv, true);
_ = recipes.label(&frame, &control, "Save");
recipes.end(&frame, &control);
if (control.response.clicked) save_requested = true;
```

`OpenControl.part` resolves another named part under the same owner. `Options.local` applies
to the root; child overrides belong in named part rules. A caller replacing a stock recipe
can retain its `.parts` and concatenate its public rule array with application rules.

| Adapter | Parts and behavior |
|---|---|
| Button | Root, label, icon and independent outside focus; caller can replace the content |
| Link and toggle button | A button's parts; a link activates on Enter only, a toggle button is `States.toggled` while pressed |
| Checkbox | Background, checked/mixed mark, label and focus; boolean and tri-state values |
| Switch | Track, moving thumb, label and focus |
| Slider | Track/root, value fill, visible thumb and focus; native drag/key behavior |
| Range | Track/root, both hit regions, fill, two visible thumbs and focus; native two-value constraints |
| Radio | Group/root, option row, circular background, mark, label and focus; native arrow/Space selection |
| Progress and spinner | Track/fill or independently styled dots; spinner has a static reduced-motion state |
| Text field and text area | Content, placeholder, selection foreground/background, caret, focus and support parts |
| Search field | A text field's parts, its root the box around the field and the Clear button; Escape or the button clears it |
| Navigation and data | Item, indicator, tab panel, header, row, cell, disclosure and separator composition |

The additional defaults are `extra_controls.radio_recipe`, `range_recipe` and
`spinner_recipe`. Both range knob dimensions and the spinner's root dimensions are explicit
finite pixel sizes in this profile; unsupported sizing modes return `InvalidValue`. Range
hit regions continue to cover the track halves while the decorative knobs are centered at
the represented values. The geometry helper maps pointer positions through the track's
transform and padding before calling the existing value behavior.

The compile-time builders are `recipes.ct.button`, `link`, `toggle`, `checkbox`,
`switchControl`, `slider`, `textfield`, `search`, `textarea`, `number`, `select` (with
`selectList`), `radio`, `range` and `spinner`. Their `Config` can bind `states_field`,
`environment_field`, `tokens_field` and `recipe_field` to ordinary application state fields.
Actual pointer/keyboard replay tests compare production draw output and semantic role/value
columns with runtime builders. A runtime resolution failure in this frontend is returned in
`ComptimeUi.Output.failure`; the host decides how to present or retry it.

The radio, range and spinner adapters replace a failed composite with the same declared
subtree of inert collapsed rows. Following controls keep their descriptor indices and remain
usable, while the first error remains explicit in the frame output. A later valid frame
rebuilds the ordinary rows. Capacity and invalid-value failures do not leave a partially
numbered tree or consume the failed component's text storage.

The compile-time optional `Widget.wakeAfter(ui, input)` hook contributes a returned wake
deadline only when its completed tree row participates in painting. The spinner uses the
bound busy state when resolving this policy; hidden/collapsed ancestors, a hidden root and
reduced motion remove its wake request. Controls without this hook acquire no timer table.
Runtime spinners use the existing frame timer and stop requesting it under the same policy.

Passive data parts leave sorting, virtualization, row identity and selection in the
application. Derive alternating or selected state from the logical item, then pass it to the
part builder; a recycled visible slot must not become the identity of that item.

### Standard navigation and overlays

`recipes.overlays` supplies dedicated menu, popover, tooltip, breadcrumb and toast
compositions over the existing widgets' state/behavior. Call floating overlays under the
root after ordinary page content. The module's `recipes` namespace contains their separate
default part recipes, and its `resolve` operation remains independently callable.

`menuTrigger` returns the normal styled button response. Pass that response with the
existing `MenuDef`, caller-owned `MenuState` and label slice to `overlays.menu`; it returns
the native one-based chosen action, or zero. `MenuOptions.style` holds the ordinary control
options, and its optional `item_states` slice supplies an exact row of authoritative states
for each item. Disabled items are skipped and read-only items do not activate.

`MenuOptions.content` optionally supplies one `MenuContent` for each declared item:
`accelerator`, `indicator` and `separator`. Accelerators and indicators are ordinary text
parts, with an independently styled spacer; a separator emits no action or label and is
skipped by keyboard navigation. Their part identifiers are `overlays.names.accelerator`,
`Parts.indicator`, `Parts.support` and `Parts.separator`. CT configurations take the same
plain slice through `menu_content` or a `menu_content_field` on caller state.

`popoverTrigger` updates a caller-owned open boolean. `overlays.popover` returns an optional
open panel; add normal `Frame` children or use `popoverText` for named recipe typography,
then call `endPopover`. Arbitrary child content is preserved. Tooltip and toast adapters
take the existing `Tip`/`ToastState`, input response or trigger, and clock from the frame.
Breadcrumb returns the activated logical link index or `types.none` and retains link/current
roles and outside focus marks.

`tooltipDecorated` accepts `TooltipOptions { style, arrow }` for an optional arrow;
`overlays.ct.Config.tooltip_arrow` selects the same part. `overlays.names.arrow` defaults to
an ordinary rotated square whose offset is relative to the bubble's border box. Its recipe
can supply caller-owned textures/materials. The arrow takes no layout or input space.
Hidden popup policy also removes its dismissal scrim. A focused read-only control can still
show its tooltip.

The `overlays.ct` namespace composes the native `Menu`, `Popover`, `Tooltip` and `Toast`
hooks with `ComptimePage`. The optional `popover.Part.text` seam applies recipe typography
only to opted-in labels. This specialized native page has no focus manager of its own:
the host supplies the trigger's `focused`/`focus_visible` state while open-menu keys and
Escape run through the existing behavior. The normal `base.ComptimeUi` is used for styled
compile-time breadcrumbs. CT overlay state holds an explicit `style_error: ?style.Error`
field by default; configuration can name another field. The first resolution error is
preserved through the frame and cleared at the next hook step.

## Behavioral and semantic state

Disabled/read-only state is authoritative input to the adapters. Paint overrides cannot
reenable activation. Disabling a captured control cancels capture; re-enabling it during the
same pointer press does not resurrect a click. Read-only editing retains navigation,
selection and copying while blocking mutations through the existing editor policy.
Radio and range preflight both the root and their interactive row part before changing
values. A state/environment rule that removes row participation cancels an existing drag or
release in both frontends; a later visible row does not revive the canceled press.

Hover, held, focus and focus-visible come from actual interaction. Selection, checked/mixed,
expanded, current, toggled, invalid, required and busy can also drive independent properties.
Application-specific combinations use `States.custom`; no table of all possible states is
allocated. Focus-within, dragging and other application states can be supplied explicitly.

Pass an optional `a11y.Semantics` to runtime adapters or call `controls.expose` with the
authoritative states. The semantic state stays a `u16`; invalid, required and busy use
previously reserved bits. `a11y.Export` preserves those bits and the AccessKit bridge sends
them to its native properties. The inspected browser shell has no DOM semantic-tree or
JSON accessibility serializer; it remains a host integration boundary.

## Environment, system colors and accessibility preferences

`Environment` is borrowed input data, not an OS query. Viewport and container sizes remain
separate. Width/height/scale ranges and boolean conditions select ordinary rules. An unknown
preference (`null`) does not match an explicit false condition. Hosts can fill the environment
from input appearance and existing accessibility settings, then supply pointer/hover,
direction, forced-color and reduced-transparency information they actually know.

Standard recipes scale their text tokens and use separate focus parts. `duration` lets the
caller suppress nonessential motion while keeping an explicitly essential animation.
`surfaceAlpha` supplies an opaque decorative-surface alternative; content/group alpha is
not indiscriminately changed. The runtime's existing reduced-motion policy still applies to
its animation path. The recipe spinner explicitly stops its phase and wake requests under
reduced motion while retaining the busy indication.

High-contrast recipes have light and dark portable palettes. `Environment.system_colors`
can supply opaque semantic colors for canvas, fields, buttons, links, selection, mark,
accent and their text colors. With automatic policy, high/forced contrast applies the final
semantic paint choices after ordinary overrides; provenance names `system.colors` as the
winner. `color_policy = .preserve` is the explicit per-component exception. The policy does
not invent host colors or claim that a custom color pair has adequate contrast.

Selection foreground is consumed by the text field and text area. When it differs from
ordinary text, clipped copies of the full shaped text paint the selected and unselected
intervals, retaining ligatures and one semantic text node. The stock text-field selection
profile has four selection bands and nine possible color intervals. Reserve up to nine
additional text rows for an active selection with a distinct foreground, plus its clipping
nodes; ordinary `widgets.textfield` remains available without this optional recipe cost.

## Locale-aware presentation

`style.locale.Locale` holds translation rows, direction, ordered font-family preferences
and numeral symbols. Labels use an explicit fallback and preserve full translated content.
`Locale.font` returns a typed text-font declaration selected from a caller font catalog;
the catalog's font handle is used, not its row index.

`Locale.iconUv` and `recipes.directionalIcon` mirror only icons explicitly marked as
directional. Photos and unmarked icons retain their orientation. `Numbers.format` maps an
exact ASCII decimal into supplied UTF-8 digits, signs, grouping and punctuation; `integer`
handles exact signed 64-bit values. Exponent, currency and percent syntax remain host
formatting choices. There is no embedded translation or locale database in this module.

For physical RTL layout, populate a caller-owned `Rtl` side table while building, then call
`locale.layoutWith`/`end` or the corresponding text-stack variants. They sequence direction
and logical padding, ordinary arrangement, physical mirroring, then finalization with the
requested pixel rounding. `ComptimeUi.frameWithPresentation` accepts the same direction and
rounding data. The source node order, semantics order and keyboard reading order remain
unchanged. Direction storage must cover every built tree row.

## Paragraph authoring

`style.paragraph` is a separate typed declaration resolver for `text_stack.Paragraph`:
alignment, last-line alignment, direction, wrapping, whitespace, tabs, letter/word spacing,
line height/leading, truncation, baseline source and shaping features retain their native
types. Use the result as `Stack.default_paragraph` or a row in `Stack.paragraphs`, then use
the existing configured text-layout path.

```zig
const p = lcgf.style.paragraph;
const paragraph = try p.resolve(.{}, &.{
    p.set(.alignment, .center),
    p.set(.line_height, .{ .multiple = 1.5 }),
    p.set(.word_spacing, 2),
    p.set(.max_lines, 3),
    p.set(.ellipsis, true),
}, .{}, null);
stack.default_paragraph = paragraph;
```

Paragraph state does not enlarge ordinary `TextStyle`. Numeric token references are accepted
only where a number has a defined meaning; for example, a line-height token is logical pixels,
while a typed literal can select font metrics or a multiplier.

## Optional authoring tools

The bounded CSS-like compiler accepts compound part/variant/state selectors, comma groups,
`:not(:state)`, comments, native property names, selected aliases and padding shorthand.
It returns ordinary rule/declaration slices and optional source locations in caller arrays:

```zig
var rules: [8]s.Rule = undefined;
var declarations: [24]s.Declaration = undefined;
var variants: [8]lcgf.types.Id = undefined;
var diagnostic: s.compiler.Diagnostic = .{};
const sheet = try s.compiler.compile(
    "root.primary:hover:not(:disabled) { color: #fff; padding: 4px 8px; }",
    .{ .rules = &rules, .declarations = &declarations, .variants = &variants },
    &diagnostic,
);
```

The source can be released after compilation. Output slices borrow the supplied buffers.
Descendant selectors, specificity, imports, cascade layers, custom-property definitions,
`!important`, URLs and unimplemented values fail explicitly. Rendering does not scan CSS
source. On error the output buffers are unspecified and no partially compiled sheet is
returned; the diagnostic provides a byte/line/column location.

`tools/stylegen/stylegen.py` is an optional Python standard-library host compiler for a
declared [DTCG 2025.10](https://www.designtokens.org/tr/2025.10/format/) subset:

```sh
python3 tools/stylegen/stylegen.py src/style/testdata/dtcg.json \
  --output generated_tokens.zig --metadata generated_tokens.json
```

It accepts all 13 token categories: color, dimension, font family, font weight, duration,
cubic Bezier, number, stroke style, border, transition, shadow, gradient and typography.
Groups, inherited types, whole-value aliases and local JSON-pointer component references
are validated before writing output. Alias cycles, missing references, wrong types, duplicate
keys, limits and unsupported format features fail with explicit diagnostics.

The generated `Tokens(lcgf)` namespace exposes scalar `entries` and typed composite `values`.
Consumers use actual font matching, paragraph layout, decoration brushes, shadow/border
painting, motion timing/curves and path dashing. Typography does not automatically instance a
variable font. Native font loading remains the host's responsibility.

The target profile records `rem` conversion (default root size 16), duration seconds and an
explicit shadow-radius-to-Gaussian-sigma factor (default 0.5). Fourteen declared color spaces
lower through native color math; packing into the existing RGBA8 color clamps at that
boundary. Missing color components, group `$extends`, remote references and arbitrary unit
expressions are rejected. The optional metadata retains the original source and resolved
token information. DTCG is a Community Group specification, not a W3C Recommendation.

## Optional storage, caches and inspection

The direct resolver borrows slices and needs no storage object. `storage.Store` is a bounded
declaration pool with generation-checked spans; exhaustion returns `NoSpace`, and reset
invalidates prior spans. Treat its wrapping `u64` generation as an epoch: do not retain spans
through a complete generation wrap, and discard them if replacing the store.

`storage.Cache` is an optional bounded cache of reached combinations. Its exact key includes
identity, part, scope, states, environment and caller revisions. Increment `recipe` when
base values, rules, local values or variant selections change; increment `tokens` for token
changes and `parent` for inherited values. `tokens.Table.generation` can summarize the active
scope chain. Clear the cache before revision wrap or reuse. Borrowed memory mutation is not
detected automatically and no background subscription graph is installed.

`inspector.snapshot` writes computed properties, winning origins, rule match reasons and
inactive/overridden/winning declarations to caller buffers. `differences` reports changed
values and their invalidation domains. No inspector window, serialization format or retained
overlay is required. System policy provenance can also be requested directly from
`Recipe.resolve` because that final policy sits above the raw rule resolver.

`style.accessibility.check` accepts the computed values, authoritative states, optional
exported semantic state, actual color samples, a known accessible name and optional hit
bounds. It reports unknown backgrounds separately from failed contrast, identifies state
mismatches, and evaluates explicit target-size policy without assuming spacing exceptions.

Focus visibility (AA), adjacent non-text contrast (AA) and changed-pixel focus appearance
area (AAA) are distinct diagnostic criteria. `focusAppearance` accepts perceived component
geometry and non-overlapping observed regions before/after focus, after clipping and
occlusion. Qualifying regions need 3:1 contrast between the same pixels; the minimum area is
the equivalent of a two-CSS-pixel perimeter. Exceptions are explicit caller observations.
These are bounded diagnostics, not a complete WCAG audit or an automatic test of focus
duration, occlusion, text reflow, neighboring target spacing or unknown preference support.
See W3C's [Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html),
[Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) and
[Focus Appearance](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html).

## Optional document typography

These modules consume shaped/measured leaves and caller-owned output buffers. They add no
ordinary label fields or mandatory work:

| Module | Supported native operations | Boundaries |
|---|---|---|
| `math_text` | Measured fractions, scripts, limits, radicals, bars, matrices; MATH constants, glyph corrections/kerns, variants and extender assembly; glyph/rule quads | No TeX/MathML parser or formula AST; caller shapes leaves and supplies script sizes; device hint corrections are not evaluated |
| `ornamental_text` | Text along polyline tangents with existing transform/clip/opacity; drop-cap exclusions; hanging edge punctuation | Path hit/caret projection remains caller work; variable line widths use the greedy breaker; hanging preserves existing breaks |
| `text_counters` | Numeric/alphabetic/symbolic/cyclic/additive UTF-8 counters, scoped stacks, affixes/padding, list marker placement and bullet quads | Declared native counter conventions, not complete CSS Counters/CLDR behavior; bounded storage and exact integer formatting |

For a drop cap, pass the returned widths to both line breaking and placement/reordering,
then apply its origins after reordering and before glyph emission or caret queries. Balanced
breaking with variable leading widths reports `UnsupportedPolicy` rather than pretending to
optimize them. For hanging punctuation, shift `Lines.x` through `hang` so emission and caret
queries agree. Mathematical composites produce inline-object boxes and baseline offsets;
the existing emitters paint the shaped children and generated rules.

## Verification

`zig build test` includes the style, component, locale, document and native consumer tests.
`python3 -m unittest discover -s tools/stylegen -p 'test_*.py'` runs importer validation.
The optional `zig build accesskit` target exercises the linked bridge when its pinned native
dependency is available. Repository execution results and platform restrictions belong in
the combined validation record; the evidence JSON names coverage without inventing results
for an unexecuted backend.
