# Zig 0.17.1: what is different from the Zig you remember

This project targets **Zig 0.17.1**. Most Zig code written before 2026, including most of what a
language model remembers, does not compile on it. Every line in this file was checked against the
0.17.1 compiler; `tools/zigcheck/zigcheck.py` re-runs those checks on your machine.

When this file does not answer a question:

1. Look at how `prototype/*.zig` does it. Those files compile and pass their tests.
2. Read the standard library source. `zig env` prints `lib_dir`; `grep -rn "pub fn name" <lib_dir>/std`.
3. Add a case to `tools/zigcheck/zigcheck.py` and run it.

Do not guess from memory, and do not "fix" working prototype code back into an older idiom.

## Will not compile any more

| Old | Use instead |
|---|---|
| `@Type(.{ .int = ... })` | `@Int(.unsigned, bits)`. For enums `@Enum(Tag, .exhaustive, &names, &values)` where `values` is `*const [N]Tag`. For structs `@Struct(...)`. |
| `std.meta.Int(.unsigned, n)` | `@Int(.unsigned, n)` |
| `@typeInfo(S).@"struct".fields` | `.field_names`, `.field_types`, `.field_attrs`: three parallel slices |
| `@typeInfo(E).@"enum".fields` | `.field_names`, `.field_values` |
| `std.meta.fields(T)` | a compile error now; use `@typeInfo` as above (`std.meta.fieldNames`, `std.meta.FieldEnum`, `@FieldType` still work) |
| `[_]u8{0} ** 4` | `@splat(0)` with a result type: `const a: [4]u8 = @splat(0);` nests: `@splat(@splat(0))` |
| `@cImport`, `@cInclude` | translate the header in `build.zig` (`b.addTranslateC`) or write `extern` declarations by hand |
| `usingnamespace` | explicit `pub const x = other.x;` |
| `async`, `await` | not in the language; I/O concurrency goes through `std.Io` |
| `callconv(.C)` | `callconv(.c)` |
| `std.ArrayList(T).init(gpa)` | `var list: std.ArrayList(T) = .empty;` then pass the allocator to every call: `list.append(gpa, x)`, `list.deinit(gpa)` |
| `std.heap.GeneralPurposeAllocator` | `var dbg: std.heap.DebugAllocator(.{}) = .init;` |
| `std.io.getStdOut()` | `std.Io.File.stdout().writer(io, &buffer)`; see the I/O example below |
| `std.fs.cwd()`, `std.fs.File` | `std.Io.Dir.cwd()`, `std.Io.File`; every call takes an `io` |
| `std.posix.write` | `std.Io` writers (or `std.os.linux.write` in Linux-only tools) |
| `std.time.Timer`, `std.time.nanoTimestamp`, `std.time.Instant` | `std.Io.Timestamp.now(io, .awake)` and `.durationTo(...)`; Linux-only tools may call `std.os.linux.clock_gettime(.MONOTONIC, &ts)` |
| `std.testing.refAllDeclsRecursive` | `std.testing.refAllDecls`, called for each container you want checked |

Still fine: `@intFromEnum` / `@enumFromInt` (the prototype uses the newer `@backingInt` /
`@fromBackingInt`; both spellings compile), `++` on arrays, `std.builtin.SourceLocation`, `@branchHint`,
labeled `switch` with `continue :label`, declaration literals (`const s: S = .zero;`),
`std.heap.FixedBufferAllocator`, `std.MultiArrayList`, `std.debug.print`, `std.fmt.bufPrint`.

## Rules that will surprise you

- **No shadowing of top-level names.** A local or a parameter may not have the name of any
  declaration in the file: `fn f(comptime State: type)` fails if the file has `const State`.
- **"ambiguous reference".** A top-level alias with the same name as a declaration inside a namespace
  (`const lanes = simd.lanes;` next to `simd.lanes` used inside `simd`) is an error. Give the alias
  another name. `prototype/ui.zig` uses `W`, `pickU`, `pickF`, `b01`, `both`, `either` for this reason.
- **An array literal cannot be indexed directly.** `[2]u8{ 5, 6 }[i]` is a syntax error; bind it to a
  `const` first.
- **Comptime loops hit the branch quota.** Reflection over many fields, or sizing buffers at comptime,
  needs `@setEvalBranchQuota(n)` at the top of the comptime scope.
- **The compiler is lazy.** A function nobody references is not analysed, so it can hide errors.
  Reference declarations from a test (`std.testing.refAllDecls(Container)`).

## Vectors (this project depends on them)

- **Plain loops are not auto-vectorized on 0.17.1.** A scalar `for` over two `f32` slices compiles to
  scalar instructions even with `-O ReleaseFast -mcpu x86_64_v3`. Anything meant to be SIMD is
  written with `@Vector`. This is why the SIMD rule in `DESIGN.md` exists.
- `@Vector` is **not allowed inside `extern struct`**. Rows that cross to the GPU (`Quad`, `Look`) use
  `[4]f32`; vectors appear in locals and plain structs only.
- Bool vectors: `&`, `|` and `!` work. `and` / `or` do not (they are control flow).
- `@select(T, mask, a, b)`, `@reduce`, `@shuffle`, `@mulAdd`, `@max`, `@min`, `@abs`, `@floor`,
  `@round`, comparisons and shifts all work on vectors.
- A bool vector becomes a bit mask with `@bitCast` to an unsigned integer of the same bit count;
  `@intFromBool` on a bool vector gives a `u1` vector.
- Load and store through slices: `const v: @Vector(N, f32) = col[i..][0..N].*;` and
  `col[i..][0..N].* = v;`
- `std.simd.suggestVectorLength(f32)` returns 4 for baseline x86-64, 8 for `x86_64_v3`, and **still 8
  for `x86_64_v4`** (AVX-512). To exercise 16 lanes the lane count has to be a build option. The
  prototype passes its tests with the count forced to 2, 4, 8 and 16.
- Columns are padded to a whole number of vectors so loops have no scalar tail. Keep that contract
  (`simd.padded`) when you add a column.

## Reflection idiom

```zig
const info = @typeInfo(Columns).@"struct";
inline for (info.field_names, info.field_types) |name, FT| {
    @field(columns, name) = carve(FT);
}
```

`std.meta.FieldEnum(State)` gives an enum of field names; `@FieldType(State, "volume")` gives one
field's type; `std.math.IntFittingRange(0, n)` gives the smallest integer type for a count. All three
are used in `prototype/comptime_ui_probe.zig`.

## I/O, arguments, files and time

The core library does no I/O at all. Tools and tests do, and the API is new: I/O functions take an
`io: std.Io` value, and `main` can receive everything it needs as a parameter.

```zig
const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const io = init.io; // also: init.gpa, init.arena, init.environ_map
    const gpa = init.gpa;

    var buf: [256]u8 = undefined;
    var out = std.Io.File.stdout().writer(io, &buf);
    const w = &out.interface;

    var args = try init.minimal.args.iterateAllocator(gpa);
    defer args.deinit();
    _ = args.next(); // program name
    const path = args.next() orelse "input.txt";

    const cwd = std.Io.Dir.cwd();
    const text = try cwd.readFileAlloc(io, path, gpa, .limited(1 << 20));
    defer gpa.free(text);
    try cwd.writeFile(io, .{ .sub_path = "copy.txt", .data = text });

    const t0 = std.Io.Timestamp.now(io, .awake); // monotonic
    const ns = t0.durationTo(std.Io.Timestamp.now(io, .awake)).toNanoseconds();

    try w.print("{d} bytes, {d} ns\n", .{ text.len, ns });
    try w.flush(); // buffered: nothing appears without this
}
```

In tests use `std.testing.io` and `std.testing.allocator`. To format into memory without any I/O:
`var w = std.Io.Writer.fixed(&buf); try w.print(...); w.buffered()`, or `std.fmt.bufPrint`.

`pub fn main() void` and `pub fn main() !void` still compile, for programs that need none of this.

## Build system

`prototype/build.zig` is a working 0.17.1 build file with test, run, object, install and
cross-compile steps. Start from it. `zig init` generates this manifest shape:

```zig
.{
    .name = .gui, // an enum literal, not a string
    .version = "0.0.0",
    .fingerprint = 0x..., // generated by `zig init`; do not invent one, do not change it later
    .minimum_zig_version = "0.17.1",
    .dependencies = .{},
    .paths = .{ "build.zig", "build.zig.zon", "src" },
}
```

- A compile step takes a module: `b.addTest(.{ .root_module = b.createModule(.{ .root_source_file = b.path("x.zig"), .target = target, .optimize = optimize }) })`.
- Forward command-line arguments to a run step with `run.addPassthruArgs()`.
- Useful flags: `-Doptimize=ReleaseFast`, `-Dtarget=aarch64-linux`, `-Dcpu=x86_64_v3`, `--summary all`.
- Single files: `zig test file.zig -O ReleaseFast -mcpu x86_64_v3`.
- `zig fmt --check .` is part of every commit's check.
- A relative `@import("../x.zig")` cannot leave the directory of the module's root file. Share code
  between directories with named modules (`.imports = &.{ .{ .name = "ui", .module = ui_mod } }`).
