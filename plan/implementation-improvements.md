# Implementation improvement plan

Reviewed on main at `eaca231`. Start with the 1,000-spring scene, then the row builder shared with the scrolling list. The unit of change is one existing function body or one private field and its writers. Keep the public signatures, caller-owned storage, pass order, tree representation, and draw-list ABI.

The source census rebuilt at this revision with Zig `0.18.0-dev.1151+8dfb7a7cc` for `x86_64_v3` passes the checked-in baseline. Three probes help choose what to change.

| Probe | What the disassembly shows | Consequence |
|---|---|---|
| `p_anim` | Eight springs per iteration, packed arithmetic and `vblendvps`. The two conditional jumps guard entry and repeat the loop. | Keep the spring integration math and its exact rest thresholds. |
| `p_sweep` | Eight column load/store pairs per row. `sete` and `add` advance the write cursor. Only the loop back edge branches inside that copy loop. | The available saving is eliminating redundant stores when the table survives intact. |

## Implementation order

1. **SIMD and branchless compaction — `simd.compact`.** Read only the `key` slice first. Compare full vectors with `want`, combine the masks, and handle the final bounded slice. Make one all-retained decision after the scan. If all rows survive, return `len`. Otherwise run the current stable, branchless copy and tail clear. This uses the existing columns and allocates nothing. The generic function accepts exact-length slices and the key may alias a moved column. Exercise lengths 0, 1, W−1, W and W+1, all kept, none kept, and alternating drops. Measure 1,000 steady springs, high churn, and tiny tween/timer tables that also call this function. Watch the added key scan on churn. An earlier probe skipping *all* finish-time sweeps saved 2.3 µs on springs, which bounds the opportunity in that run. [Compaction and reference tests](../src/core/simd.zig) · [Frame.finish](../src/runtime/frame.zig) · [Sweep measurement](../docs/perf/port-perf.md)

2. **Avoid initialization on a known slot hit — `Anims.slot`, then `Tweens.slot`.** On the existing predicted-ID hit, advance `next` and return the known row directly. Today even that hit enters placement bookkeeping. Springs write the ID and spare-row initial values, and tweens select and write existing values back to several columns. Inspect the optimized caller first to see which writes survive. Keep the SIMD fallback search, full-table last-row behavior, and the branchless `slotScan` path used by FLIP. Benchmark the spring change on build time before applying the same idea to tweens on a tween workload. Verify first use, reordered/repeated IDs, saturation, sweep reset, and reduced motion. [Spring slots](../src/anim/anims.zig) · [Tween slots](../src/anim/tweens.zig) · [FLIP](../src/anim/flip.zig)

3. **Simplify leaf construction — `Frame.leaf`.** Inspect a compiled list builder for stack/depth bookkeeping and a second subtree-end store. A leaf currently calls `open` and `close`, while `Tree.pushRow` already sets its end to `i + 1`. Test a direct push under the current parent at ordinary depths. Retain the saturated-depth behavior of the existing pair, including the overflow flag, resulting depth and parent of the next sibling. Compare the active stack, tree links, text/custom links and draw output with explicit open/close at the depth boundary and at node capacity. Measure list, rows and springs build time and ReleaseSmall size. Keep the shorter path only if it removes real work after optimization. The existing rare-extras branch in `pushRow` has already beaten unconditional stores in the rows benchmark. [Frame builder](../src/runtime/frame.zig) · [Tree row writes](../src/core/tree.zig) · [Previous build experiments](../docs/perf/port-perf.md)

### Follow-up work by workload

| Function | Local change | What decides adoption |
|---|---|---|
| Measurement cache `lookup/store` and shaping cache `get/put` | Both generated keys use `hash \| 1` and both tables index with `key & mask`. With two or more power-of-two slots every even slot is unreachable for those keys. Derive the slot from `(key >> 1) & mask` consistently on read and write. Preserve key values, empty marker, allocation and replacement policy. | Demonstrate two distinct generated keys coexisting in two slots, a real collision replacing its occupant, and identical measured extents and shaped glyphs. Record warm hits, misses and elapsed time over a repeated text set near capacity. The standard frame text scene uses Mono. [Measurement cache](../src/text/protocol.zig) · [Shaping cache](../src/text/shape/cache.zig) |
| `incremental.applyTextKept` | Each kept subtree currently triggers two SIMD ranks over the entire text-node column per axis. Text runs and disjoint kept subtrees are already ordered. Walk the text cursor forward through gaps and kept intervals, applying extents only in the gaps. Keep the empty-kept path a single scatter loop and keep the generic rank contract. | Compare both axes with the existing implementation, including text at the kept root, at the exclusive end, adjacent kept roots and no text. Vary kept-root count at fixed text count, including zero and one. Prefer the simplest walk that wins on many roots and holds the common case. [Incremental layout](../src/layout/incremental.zig) |
| Software `Framebuffer.fill` | After clipping and packing the color once, try filling the exact `u32` span of each row with `@memset`. Inspect the stores the pinned compiler emits. An explicit unmasked SIMD interior is worth trying only if the simpler span fill falls short. | Time narrow and wide spans, clears and tiled/scissored fills in pixels per second. Check empty and unaligned boxes, RGBA/BGRA, neighboring pixels, stride padding and `sw-golden`. The release frame benchmark ends at a draw list. [Software fill](../src/render/sw/sw.zig) · [Software golden job](../ci/jobs/sw-golden.sh) |

## Unused members and the remaining plan

**Remove Android’s private `Shared.resized` flag.** The resize callback sets it and `sync` clears it. Neither reads it. Polling samples the native window dimensions directly. Delete the field and both writes while preserving the callback’s generation increment, lock, and looper wake. Run the host replay tests and `ci/run.sh android` for both Android build modes. Treat this as a readability improvement. Struct padding may absorb the byte, and the Android job cross-builds the native shell. [Android callback, sync and poll](../src/shell/android/android.zig) · [Android CI coverage](../ci/jobs/android.sh)

For further removals, trace readers through `@field`, generic column copies, both front ends, platform targets and shader offsets before deleting a field. Two concrete examples worth retaining are the animation `node` columns used by subtree reuse and the inherited `alpha` read by quad and text paint. Record any footprint improvement using `@sizeOf` or `Context.requiredBytes` at the same limits. [Reuse](../src/runtime/reuse.zig) · [Opacity inheritance](../src/draw/inherit.zig) · [Paint](../src/draw/paint.zig) · [Pinned Quad layout](../src/draw/draw_list.zig)

## Acceptance for each implementation change

Use the pinned Nix shell. Build before/after from the same parent, alternate the binaries on one quiet core for at least five rounds, and record the targeted pass median, p99, whole-frame or poll time, and run-to-run spread. For cache, kept-text and pixel work, time a fixture that exercises the changed function. Keep a speed optimization when the intended workload improves beyond the spread, output matches and the control workloads stay within noise. A cleanup can stand on simpler code with equivalent output and cost.

- Use `zig build bench -- --core=src --scene springs` and repeat for list and rows. The bench checks first-frame draw-list equality with the prototype. Also compare subsequent frames for changes involving sweep, reuse or input state. Check idle polls and wake behavior. Use the same-machine `gates-vs` job when reporting a release-gate change. [Alternating-run script](../docs/perf/bench-src/alt2.py) · [Gate definitions](../bench/gates/README.md)
- Run `ci/run.sh census-src` and inspect the affected symbol with `objdump -d -M intel --disassemble=p_sweep zig-out/census_src.o` or its equivalent. Identify each new conditional jump as loop control, once-per-call dispatch, or a per-row decision. Use the existing branch budget and document a measured reason for any proposed change to it. The prior vectorized paint-flag experiment had identical 37.6 µs medians despite fewer instructions. [Census job](../ci/jobs/census-src.sh) · [Paint experiment](../docs/perf/paint.md)
- Run `zig build test`, the affected replay/golden job, and the lane-width jobs (2, 4, 8 and 16) for vector or padding changes. Use `zig build size` for hot-path specialization and field removals. Keep the source change, timing evidence and correctness check together. [CI checks](../docs/CHECKS.md)
